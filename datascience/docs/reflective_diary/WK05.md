**Date:** 30 August 2026
**Role:** MDS — Data Science / Data Engineering
**Iteration:** 1 (demo Tuesday 1 September)

---

## What I attempted

Take KinderPrint from zero data to a working Iteration 1 data layer: acquire and
validate the source datasets, decide the analysis geography, clean and integrate
three sources, build the priority and matching models, and deliver something the
backend team could actually load.

Specifically: AEDC 2024, ABS SEIFA 2021, ABS Census 2021, ABS ASGS Edition 3
boundaries → 346 Greater Melbourne communities → priority model → community
matching → five JSON artefacts consumed by the FastAPI service.

---

## What I learned

**Verify the data before designing around it.** I began by listing four things
about the AEDC file that could each break the project, then answered all four by
inspection in one sitting rather than assuming:

| Question | Answer | Consequence |
|---|---|---|
| Are child counts published? | **Yes** | Confidence intervals and significance testing possible |
| Which ASGS edition? | **Edition 3 (2021)** | Main join is clean |
| How is suppression encoded? | `#` = ≤3 children; `*` = <15 valid scores, <2 teachers, or <80% coverage | Three-state quality flag, no imputation |
| Residence or school assignment? | **Residence** | Environmental joins are meaningful |

**"Latest release" is not the same as "correct".** ABS released ASGS Edition 4 in
July 2026 and it is now their default download, but every analytical dataset I
have (AEDC 2024, SEIFA 2021, Census 2021) is on Edition 3. Edition 4 SA2 codes
partially match Edition 3 codes, so the join would have succeeded and been
silently wrong. I pinned Edition 3 explicitly and recorded it as a RED row in the
compatibility matrix.

**Small samples make differences unreliable.** The median Greater Melbourne
community has only 122 children assessed. At that size a 95% confidence interval
around a 22% reading spans roughly ±7 percentage points.

---

## What failed

**Handover v1 was the wrong format.** I built CSVs and a PostgreSQL schema before
reading the backend code. When I did read it, the service reads five JSON files
from environment-variable paths — no database at all. I rebuilt as JSON. Half a
day lost, but caught two days before the demo rather than on the morning.

**A NaN bug that the backend caught, not me.** My first `profiles.json` marked
environmental indicators as `available` while their value was null, because
`NaN is not None` evaluates to `True` in Python. Their `validation.py` rejected
all 346 records. Fixed by normalising the value first and judging availability
afterwards. This is the strongest argument I have for testing against the
consumer's real validator instead of my own assumptions.

**Aggregate SMD did not discriminate between matching models.** Standardised mean
difference across M0–M3 ranged only 0.025–0.064, and M2 scored slightly worse
than M1. In a symmetric design where every unit is both a source and a match, the
aggregate means are near-identical by construction, so the metric carries little
information. I switched to per-pair distance distribution, match coverage, and
geographic plausibility as the real diagnostics.

---

## Why it failed

The v1 format error was assumption over verification — the same failure mode I
had explicitly guarded against for the datasets, applied carelessly to a
teammate's code. The NaN bug was a type-boundary error: pandas missing values do
not behave like Python `None`. The SMD problem was importing a metric from the
causal-inference literature (where treated and control groups are distinct)
into a design where every unit appears on both sides.

## What the data showed

**H2 — SEIFA vs AEDC vulnerability.** Spearman −0.654 (p = 4.6e-43), Pearson
−0.668. IRSD explains **44.6%** of variance in developmental vulnerability.
**55.4% is unexplained.** This tests rather than assumes the project premise: if
disadvantage explained nearly everything, KinderPrint would have no space to
operate in. It does not.

**The V0 problem, measured.** Priority V0 (percentile overlap across four
indicators) correlated **0.795** with disadvantage. It was reproducing a
disadvantage map — exactly what the project brief says the product must not be.

**V1 result.** Weighted residual model, correlation with disadvantage **0.014**.
Top-20 overlap between V0 and V1 is **2 of 20** — the two methods identify almost
entirely different communities. V1 surfaces Toorak (IRSD decile 10, 26%
vulnerability), which no disadvantage-driven method would ever flag.

**Uncertainty.** Of 273 matched pairs, **204 (74.7%) have differences within
sampling variation**. Among Higher-priority communities the ratio inverts: 11 of
17 are significant.

**Study population.** 342 of 346 communities analysable. 4 excluded (East
Melbourne, Flemington Racecourse, West Melbourne Industrial, Royal Botanic
Gardens) — a CBD apartment area, a racecourse, an industrial estate and a park.
**Zero values imputed.**

**Convergent exclusion.** SEIFA excludes 5 Melbourne SA2s for low population; 3
are ones AEDC independently merged into neighbours. Two agencies handling the
same near-empty areas the same way is stronger evidence that the exclusions are
appropriate than any claim I could make myself.

## What requirement changed

**Analysis unit redefined.** AEDC merges some SA2s to meet its minimum child
count — 13 groups in Greater Melbourne, seven of them outer growth corridors
(Wollert, Mernda, Craigieburn, Cranbourne East, Clyde North, Cobblebank, Fraser
Rise). I had assumed one community = one SA2. Changed to "AEDC reporting area"
with a `community_sa2` bridge table and dissolved geometry. Dropping the merged
rows would have lost the growth-corridor communities the project most cares about.

**Comparison must carry uncertainty.** Because child counts exist, every
matched-pair difference now returns a significance state. Requested that the
backend contract carry the field rather than retrofit it.

**Scope narrowed to Greater Melbourne.** Constrains matching to one climate zone
and one remoteness class, removing a large confounder for free.

---

## What model changed

| Version | Method | Trigger for change | Result |
|---|---|---|---|
| Priority V0 | Percentile-threshold overlap | Correlation 0.795 with disadvantage | Rejected — reproduces a disadvantage map |
| Priority V1 | Weighted residual model, banded | — | Correlation 0.014; adopted |
| Match M0 | Unscaled Euclidean KNN | Dominated by large-scale features | Superseded |
| Match M1 | Standardised Euclidean | Correlated covariates double-counted | Superseded |
| Match M2 | Mahalanobis | Geographically implausible pairs | Superseded |
| Match M3 | Mahalanobis stratified within SA4 + caliper | — | Adopted; 79.8% coverage, 73 `no_match` |

V1 is weighted by children assessed, so a community with 40 children influences
the fit less than one with 400.
